How it goes

Ask. Argue. Rule.

  1. Put the question

    /new should retries use exponential backoff? — every seat catches up on the thread and answers at once. A round is concurrent, so nobody anchors on whoever spoke first.

  2. Let them disagree

    They object, cite, and ask each other directly. An outstanding question narrows the round to whoever was asked — and a question put to you stops the room until you answer it.

  3. Close it, and keep it

    /approve 3 agreed — cap at 6, then /conclude. Minutes are written: what was asked, what was decided and by whom, who objected, and what was left unanswered.

Why this way

The disagreement is the product.

One model with a long prompt gives you a confident average. Independent seats — each with its own context, its own model, its own reading of the sources — give you the objection.

  • You hold the decision

    There is no moot_decide tool for an agent to call — not a disabled one; it does not exist. Only a human closes a proposal or ends a meeting, checked in the store rather than asked for in a prompt.

  • Your subscriptions, not an API bill

    Moot never calls a model or holds a key. It drives the first-party CLIs, so each seat runs on the plan you already pay for — and a cheap question can go to a cheap seat.

  • Work, not just talk

    Switch a topic to work and a manager drafts tasks. The plan comes to you as one proposal; approved work runs in isolated git worktrees. Your branch is never touched, and merging stays your git action.

  • It cannot quietly spend your quota

    Per-seat turns, per-topic rounds, per-hour wakes — and a failed wake counts, because a metered CLI charges for it. Every ceiling pauses for a person instead of continuing.

Measured, not guessed

Latency is inference, not transport.

On a real council prompt, the reasoning effort setting is worth roughly nine times what the transport is. Persistent sessions — the thing that looks like the fix — would save about two percent.

Install

One command sets it up.

pip install -e .

moot setup            # finds your CLIs, seats them, registers, and proves it works
moot tui

moot setup detects which agent CLIs are installed, registers a seat for each, wires up the MCP servers that need it, and spends one real turn per seat to prove it can reach the board. Everything it does has a plain command behind it if you would rather do it by hand.

It checks the board, not the exit code. A CLI can start, load the MCP server, decline to call it and exit 0 — a return-code check goes green while the seat is mute.
